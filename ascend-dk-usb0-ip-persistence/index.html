昇腾 Atlas 200I DK 管理口 IP 持久化：踩坑、根因与常驻 watchdog 方案

Posted on 2026-10-05 In edgePerception
昇腾 Atlas 200I DK 每次重启后 usb0 的固定 IP 都会掉回出厂地址，害得 SSH 连不上。本文复盘这个"配得好好的 IP 为什么会掉"的坑，讲清三套网络管理并存的根因，并给出一个开机自启、常驻自愈的 systemd watchdog 持久化方案。

硬件：Huawei Atlas 200I DK A2（Ascend 310B）
系统：板载 Ubuntu 22.04（hostname davinci-mini）
场景：Windows PC 通过 USB（RNDIS gadget）连板子做 SSH / VSCode Remote-SSH 开发

0. 为什么要写这篇

如果你手上有一块 Atlas 200I DK，大概率踩过这个坑：

  • 官方/README 教你手动 ip addr add 192.168.137.2/24 dev usb0 设管理口 IP；
  • 当时连上了，开心；
  • 一重启 / 一拔 USB / 板子睡一觉断电，IP 又变回出厂的 192.168.0.2，SSH 全部失联，得拿串口或重新手动配。

我在这个问题上反复折腾过两次（7 月一次、这次一次），每次都以为”配好了”，结果又掉。最后用串口把启动过程扒了个底朝天，才搞明白根因不在”没配”，而在”有人在你配完之后又改回去”。这篇文章把结论沉淀下来，给以后的我，也给同样被这块板子折磨的学习者。

配套代码在仓库 edge-perception-bench 的 scripts/board/ 与 docs/DK网络持久化配置.md。

1. 先搞清楚拓扑：这块板子怎么连网

Atlas 200I DK 用一个很”物联网”的方式连 PC —— USB 网络（RNDIS gadget），不是网线也不是 WiFi：

  • 板子把自己伪装成一块网卡插到 Windows 上，Windows 里看到的就是 “USB RNDIS6”。
  • 你在 Windows 上对上网网卡开 ICS（Internet 连接共享），共享给这块 RNDIS 网卡，Windows 就会在这个 192.168.137.0/24 网段里当网关 .1。
  • 板子侧对应接口叫 usb0，我们要把它固定成 192.168.137.2，SSH 就走它。

冷知识：这块 gadget 网卡的 MAC 每次开机都会随机化。这本身正常，但会让 Windows 的 ARP 缓存短暂失效——排查时别被它带偏。

2. 需要配置什么（结论先行）

分两端，都是一次性配置，配好后长期自动生效：

① Windows 端：ncpa.cpl → 右键你的上网网卡 → 属性 → 共享 → 勾选，选 “USB RNDIS6”。

② DK 端：装一个开机自启的常驻 systemd 服务 dk-usb0-fix.service，它替你死死盯住 usb0 = 192.168.137.2。

装完立刻生效，之后无论重启、拔插、断电重来，137.2 都会自己回来。不用再手动 ip addr add。

3. 为什么要这么配：三套网络管理”打架”的根因

这是全文最值钱的部分。先说为什么”手动 ip addr add“和”配了 networkd 静态文件”都不管用。

3.1 ip addr add 天生不持久

ip addr add ... 是运行时配置，只写进内核当前状态，不落任何配置文件，重启即失效。这是最表层的原因。

3.2 那写成 networkd 静态文件呢？—— 板子上同时跑三套网络管理

板载 Ubuntu 22.04 上，systemd-networkd、NetworkManager、connman（connmand）三套东西并存，对同一个 usb0 各写各的：

机制 配置来源 对 usb0 干了什么
systemd-networkd /etc/systemd/network/10-usb0.network（Address=192.168.137.2/24） 开机早期设成 137.2 ✅
connman /etc/connman/main.conf 中后期可能把 usb0 拿去做出厂/DHCP 配置 ❌
厂商晚到 setter 找不到配置文件，疑似二进制/configfs 工具 开机后期单次把 usb0 改回出厂 192.168.0.2 ❌

我在板子上全盘 grep 0.2 这个地址，任何配置文件里都找不到——说明它是被某个二进制/固件工具在运行时直接写进去的。

3.3 决定性证据：串口实测”晚到的改写”

因为 SSH 反复失联，我干脆接了 USB 串口（PL2303，ttyAMA0） 直接看板子内部。实测发现：

  • 重启后 usb0 一度确实是 137.2；
  • 但开机进行到后期，有一个只发生一次的动作把它改回 192.168.0.2；
  • 这个动作发生的时间点，晚于 networkd、晚于 systemd oneshot、晚于 udev add 触发。

这就是为什么 7 月和之前的尝试全失败：凡是”开机只跑一次”的方案，都跑在这个破坏者之前，抢不过它。 你配一次它改一次，永远输。

4. 方案：把”配一次”换成”常驻巡检自愈”

既然抢不过”晚到 + 单次”的改写，那就别指望一次性配对了——用一个常驻后台进程，周期性把 IP 夺回来。最坏 15 秒内自愈，破坏者来得再晚、来几次都没用。

4.1 watchdog 脚本 dk-usb0-fix.sh

4.2 systemd 服务 dk-usb0-fix.service（开机自启 + 常驻 + 挂了自动重启）

关键点：Type=simple（不是 oneshot！oneshot 跑完就退出，正好被晚到改写打回原形）+ Restart=always 让循环常驻。

4.3 udev 规则 90-usb0-net.rules（覆盖 USB 热插拔）

4.4 顺带把冲突源降低（可选但推荐）

  • connman 黑名单加 usb0：/etc/connman/main.conf 里 NetworkInterfaceBlacklist=...,usb0，让 connmand 别再托管管理口；
  • rc.local 去冗余：删掉旧的 ip addr add 137.2 和会覆盖 /etc/resolv.conf 的行；
  • netplan eth1 冲突：eth1 曾配了 192.168.137.100/24，和 usb0 同网段导致路由歧义，改成 dhcp4: false + optional: true（改 netplan 一定先 netplan generate 校验，别直接 apply，小心把自己关在门外）。

改这些之前，我把原始配置全备份到了板子 /root/netbak-20261005/。动别人设备的系统配置，先备份、可回滚，这是底线。

5. 配置后的影响 / 代价

正面：

  • 开机 / 拔 USB / 断电重来，192.168.137.2 自动稳定回来；
  • VSCode Remote-SSH、ssh ascend-dk 直连，再也不用摸串口或手敲 ip addr add。

代价与注意点：

  • 多了一个几乎不占资源的常驻进程（每 15 秒醒一次）；
  • 如果你手动想把 usb0 改成别的 IP，最坏 15 秒内会被 watchdog 夺回 137.2——这是设计行为。调试时先停：

6. 复盘：这次踩坑学到的东西

  1. “配了又掉” ≠ “没配对”：先怀疑有没有别的进程在你之后改。这块板子上三套网络管理并存 + 一个二进制 setter，就是元凶。
  2. 抢不过”晚到”，就改成”常驻”：一次性配置打不赢运行时的反复改写，用周期巡检自愈是通用解法（K8s 的 controller-reconcile 环也是这个哲学）。
  3. SSH 失联时，串口是最后的真相来源：很多”网络层看不到”的问题，接上 ttyAMA0 一进系统就豁然开朗。
  4. Windows→Linux 推公钥会带 BOM/CRLF 毒：这次配免密时，type pub | ssh "cat>>" 让 authorized_keys 混进 UTF-8 BOM(M-oM-;M-?) 和 \r，sshd 直接忽略整行、免密失效。用板子侧 printf 重写才干净。跨平台传文本永远要警惕行尾和编码。
  5. 改系统配置：只读诊断先行、备份、可回滚、重启验证——四步一步不能省。
