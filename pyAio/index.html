多进程

Python多进程是一种通过操作系统级资源分配实现并发执行的技术，其核心在于利用多个独立的进程并行处理任务。

功能说明

  • 并行计算

    Python多进程通过 multiprocessing 模块实现真正的并行执行，每个进程拥有独立的内存空间和执行环境，可同时利用多核CPU。

  • 资源分配与隔离

    进程是操作系统分配资源的基本单位，每个进程独立运行，互不干扰。进程的动态性体现在其生命周期中，从创建到终止均由系统管理。多进程的隔离性使其在稳定性上优于多线程，尤其适合CPU密集型任务。

  • 通信与同步机制

    • 进程间通信（IPC） ：通过Queue（队列）、Pipe（管道）、Manager（共享内存）等工具实现数据传递。Queue适用于主进程与子进程之间的数据交换，而Manager支持复杂数据结构的共享。
    • 同步原语：使用Lock、Barrier等同步对象协调多个进程的执行顺序，避免竞争条件。

  • 进程池管理

    multiprocessing.Pool 简化了批量任务的并行处理。通过 pool.map() 可以将任务分配给进程池，自动管理进程生命周期。

注意事项

  • 性能开销

    • 进程启动成本：每次创建进程需复制内存和资源，开销远高于线程。一般根据服务器配置调整进程数量，避免过度消耗。
    • 通信开销：进程间通信（如Queue）需额外开销，需权衡效率与复杂度

  • 守护进程设置

    • Windows系统要求进程代码位于if name == ‘main‘块内，否则可能导致死循环（当然，好的IDE你不写在if name == ‘main‘块内，会自动报错）
    • 守护进程的 daemon 属性需谨慎设置，避免主进程退出时子进程残留

  • 同步与竞争条件

    • 共享内存风险：直接共享变量（如全局变量）可能导致数据不一致，需使用Lock或RLock同步。另外子进程与父进程不共享内存空间，即子进程获得父进程环境变量的独立副本，子进程对环境的修改不影响父进程，反之亦然
    • 死锁问题：多进程间的同步逻辑需避免死锁，例如使用Barrier协调多个进程的等待状态

多线程

功能覆盖

  • 并发处理

    多线程可同时执行多个任务，例如文件读写、网络请求等I/O密集型操作，避免主线程阻塞，提升程序响应性

  • 任务分解与并行执行

    将复杂任务拆分为子任务，通过多线程并行处理，缩短总耗时。例如，爬虫任务中可同时抓取多个网页(网卡也是IO设备)

  • 资源共享与通信

    线程间共享进程内存空间，便于数据传递和协作，但需注意同步问题

  • 适用场景

    • I/O密集型任务：如文件读写、网络请求、数据库操作等，线程在等待I/O时可切换执行其他任务。
    • 用户界面优化：GUI应用中，后台任务（如进度计算）可与界面交互，避免卡顿。
    • 异步任务处理：如定时任务、监控任务等，可通过多线程实现非阻塞执行

实现方法

  • 基础模块

    Python通过threading模块实现多线程，其核心功能包括：

    • Thread类 用于创建线程，支持两种方式：

      • 基于函数：直接指定任务函数
      • 基于类继承 自定义类继承Thread，重写run()方法

  • 高级功能

    • 锁机制：使用 Lock 、RLock 等同步原语保护共享资源，避免数据竞争
    • 守护线程：通过 setDaemon(True) 设置子线程随主线程结束而终止
    • 线程池：通过 concurrent.futures.ThreadPoolExecutor 管理线程池，简化并发任务调度

注意事项

  • 全局解释器锁（GIL）

    Python的GIL确保同一时间仅有一个线程执行字节码，导致CPU密集型任务无法真正并行

    • 解决方案

      • I/O密集型任务：利用多线程并发处理，提升效率
      • CPU密集型任务：改用多进程（multiprocessing）

  • 线程安全与同步

    • 数据竞争：多个线程访问共享变量时可能导致不可预测的结果，需使用锁或信号量同步
    • 死锁：避免锁的嵌套或循环等待，确保锁获取顺序一致
    • 异常处理：线程异常不会自动终止程序，需通过try-except捕获异常

  • 性能优化

    • 线程数量：过多线程会增加上下文切换开销，建议根据CPU核心数合理分配
    • 守护线程：设置daemon=True可避免孤儿线程占用资源。
    • 资源管理：及时释放锁（如lock.release()）防止死锁

Python多协程的核心概念

  • 定义与原理

    多协程（Coroutine）是一种用户态的轻量级线程，通过协作式多任务实现并发。与操作系统线程不同：

    • 切换开销极低：协程上下文切换发生在用户空间，无需内核介入

    • 非抢占式调度：由事件循环（Event Loop）管理，协程主动让出执行权（await）时才会切换。

    • 适用于IO密集型任务：如网络请求、文件读写等阻塞操作，在等待期间自动挂起并执行其他协程

  • 与线程/进程的对比

    维度 协程 线程 进程
    切换开销 微秒级（用户态切换） 毫秒级（内核态切换） 最高（资源独立）
    内存占用 KB级（动态扩缩容） MB级（固定栈大小） GB级（独立内存空间）
    并发能力 单进程可支持数万协程 受限于OS线程数（通常数百） 数十个
    适用场景 IO密集型（网络/文件） IO/CPU混合型 CPU密集型
    GIL影响 不受限（单线程事件循环） 受CPython的GIL限制 无影响

多协程的具体实现与使用

  • 核心库：asyncio

    Python通过asyncio标准库提供协程支持，核心组件包括

    • 事件循环（Event Loop） ：调度协程的核心引擎。
    • 协程函数（async def） ：定义异步任务，返回协程对象。
    • 任务（Task） ：由 asyncio.create_task() 创建的调度单元
